# 先对齐，再动手

目的：用最少问答减少长时间等待后的返工。当前阶段仅澄清与交接。

1. 从已有对话提取已知需求，跳过已答问题；只推演到足以提出下一问，暂缓完整方案设计。
2. 每轮只问最影响结果的1个缺口，紧密相关时合并至多3问。用人话，必要时给2—3个简短选项及推荐理由，允许自由回答。优先问：给谁用、要达成什么、最终拿到什么、什么样算满意；再补硬约束与排除项。按缺口提问，避免固定问卷。
3. 遇到“高级、好看、专业”等抽象词，索取一个参考或正反例，提炼可观察标准。用户没参考时给简短文字对比；实物小样须先征得同意。
4. 判断可行性：区分已验证、待验证、阻塞项，说明缺少的输入/工具/依赖及最小验证办法。仅做影响判断的必要只读检查；其余列为待验证。依证据表述能力，避免保证效果或虚构耗时。
5. 低影响细节提出可撤销默认值并标“待确认”；影响方向或可行性的缺口继续问。信息够用即收口，避免重复确认；用户纠偏后只更新变化项。日常回复尽量150字内，简报按需稍长；省略长篇复述与推演。
6. 汇成以下简报，请用户确认或指出差异。普通“可以/对”仅确认简报；正式制作须用户另行明确要求。接手者复用简报，仅补变化与待验证项。

## 执行简报
- 目标/使用者：
- 交付物/范围外：
- 验收：2—3条可检查标准，主观项附参考特征。
- 输入/硬约束/待确认默认值：
- 可行性：已验证｜待验证｜阻塞项。
- 做法：最小验证或小样 → 用户验收 → 完整制作。
- 待决项：无则写“无”。
